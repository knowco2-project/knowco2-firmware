# KnowCO2 web-portal localization

The browser settings portal supports **50 languages**. The device's 240 × 135
TFT remains English-only because its built-in bitmap font is intentionally
small and does not contain the glyphs required by the additional scripts.
The portal is rendered by the user's phone or computer, so it can use the
browser's installed fonts without adding font files to the firmware.

## Supported languages

The original instant-switching pack contains 22 languages:

English, Spanish, French, German, Brazilian Portuguese, Italian, Dutch,
Swedish, Polish, Czech, Russian, Ukrainian, Turkish, Vietnamese, Indonesian,
Hindi, Bengali, Tamil, Thai, Japanese, Simplified Chinese, and Korean.

The compact extension pack adds 28 languages:

Danish, Norwegian Bokmål, Finnish, Romanian, Hungarian, Slovak, Greek,
Bulgarian, Croatian, Slovenian, Catalan, European Portuguese, Arabic, Hebrew,
Malay, Filipino, Traditional Chinese, Afrikaans, Swahili, Estonian, Persian,
Urdu, Marathi, Telugu, Gujarati, Kannada, Malayalam, and Nepali.

Arabic, Hebrew, Persian, and Urdu set the document direction to right-to-left.
Language tags use BCP 47-compatible values where a regional distinction is
required: `pt-PT` and `zh-TW`. The existing `pt` value remains Brazilian
Portuguese for backward compatibility with saved device settings.

## Size-conscious architecture

`translations.py` remains the base pack. These languages are included in each
settings-page response so existing behavior stays instant.

`translations_extra_1.pack` through `translations_extra_5.pack` are indexed
binary files. Each has a small ASCII header followed by independent
zlib-compressed JSON value arrays. Array positions match the English key
order, and values identical to English are stored as JSON `null`. The firmware
finds the selected locale, seeks directly to it, and inflates only that row.

Five regional pack files keep individual files easy to audit while using only
13 allocation clusters (52 KiB on a 4 KiB FAT volume), versus at least 28
clusters for one file per language. Only the currently saved extension
language is sent to the browser. Selecting a different extension language
submits the existing settings form once and reloads the page with that
language. A blank settings-password field is disabled before this automatic
submission so a language change cannot accidentally clear an existing
password.

The complete 28-language extension set has an automated **52 KiB FAT-allocation
budget**. Each compressed locale is limited to 2 KiB and each inflated locale
to 8 KiB. The browser JavaScript uses one shared key array plus positional
value arrays rather than repeating all 89 key names for every language.

## Validation

Run:

```sh
python3 tests/test_i18n.py
```

The suite checks:

- all 50 catalog entries are unique and ordered consistently;
- every base language has exactly the English key set;
- every extension language has exactly 89 positional values;
- every packed offset, compressed size, and inflated size is valid;
- the real runtime loader can read every extension language;
- every portal `data-i18n`, placeholder, and ARIA key exists;
- protected URLs, MQTT examples, `CO₂`, `ppm`, and `180°` survive translation;
- right-to-left selector metadata is present;
- the compact payload is smaller than the previous repeated-key object;
- the extension data stays inside its flash and per-locale memory budgets.

The 2026-09 audit also corrects high-confidence spelling or terminology
problems in the legacy Polish, Czech, Turkish, Swedish, Dutch, Russian,
Ukrainian, Japanese, Simplified Chinese, and Korean strings.

## Translation-review status

These strings have automated structural validation and a multilingual
editorial review. They are **not represented as certified native-speaker
translations**. Before paid advertising or support material targets a
specific locale, have a native technical reviewer check that locale in the
actual portal. Keep product names, protocols, URLs, units, and identifiers
unchanged.

When changing English text, rebuild the extension pack and update all base
dictionaries in the same pull request. The tests intentionally fail when a
key is missing, added in the wrong order, duplicated, corrupted, or allowed
to exceed the localization budget.
