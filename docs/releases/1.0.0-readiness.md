## Important unresolved blockers

Full staging is **not** atomic whole-image activation. The current commit loop
still removes/replaces live files one at a time and can be interrupted between
operations. `code.py.bak` is not a complete rollback. Completion is recorded
before a successful candidate boot. Automatic recovery from a real power loss,
coherent rollback, independent pre-import recovery, health confirmation and
safe settings migration remain REQUIRED before customer OTA.

The lock intentionally still describes the old **10.2.1** engineering profile
with the **20260520 bundle + SCD4X 1.4.13** override. It is not approved for 1.0.0.
Mike's USB-tested flasher profile used **10.3.2 / 20261112**. Do not weaken the
signed runtime/library checks or claim these profiles interchangeable. Choose,
pin, and qualify the actual release tuple in a follow-up integration change.
The flasher's source compiler may select its own library bundle; the exact
bytes on the device must match the signed profile, including the override.

As verified from upstream on November 16, 2026, CircuitPython 10.3.2 removes
compromised root certificates (eMudhra emSign and AAA Certificate Services):
https://github.com/adafruit/circuitpython/releases/tag/10.3.2
An application-only OTA cannot replace CircuitPython's built-in CA bundle.
Do not move the target back to 10.2.1 simply to satisfy the old test lock.

Current ESP-IDF advisories must be mapped to the exact embedded IDF commit and
build configuration, including the lwIP DNS-cache advisory
https://github.com/espressif/esp-idf/security/advisories/GHSA-ch63-jxm5-vmvf
No applicability/fixed-version conclusion is claimed here. Upstream's index:
https://github.com/espressif/esp-idf/security/advisories
Absence of published CircuitPython advisories is not evidence of no issues.

The original security preview is scoped to one exact bootstrap build. It does
not demonstrate a full release upgrade or a driver migration. Rebuild artifacts
for this exact integration commit; do not reuse #22's old fixture bundle. No
combined device artifact is approved by this change.

## Release gates and evidence

`1.0.0-gates.json` is the mandatory blocker ledger. Run:

```
python3 tools/release_gate.py --report
python3 tools/release_gate.py --enforce
```

The report command reports blockers but succeeds for engineering CI. Enforce
fails until all required evidence and authorization are present. Even then,
the integration release workflow deliberately has no publishing implementation.
A separate reviewed signing/release change is required. The ledger alone is
not cryptographic attestation or a substitute for exact-artifact testing.

Required tests include configured version-A to distinct version-B upgrades;
all protected settings, identity and calibration; failure injection before/
after every persistent operation; fresh-process boot/recovery; interrupted
upload; candidate first-boot failure; repeated updates; near-full FAT storage;
USB ownership; sensor/UI/buttons; real Wi-Fi/cloud continuity and TLS negative
cases; controlled physical power cuts and a defined soak. A cold process must
not inherit old modules from memory and hide a broken mixed installation.

Test key devices belong on an isolated test network with synthetic credentials.
The public RSA fixture is deliberately insecure; anyone can sign for it. Never
ship it, import customer credentials into tests, or run manufacturing erase as
an OTA preservation test. Use a spare board only after host acceptance gates.

Repository `main` reported unprotected during this review. Branch/tag rules,
required checks and release approval are additional release controls to verify;
this task does not change administrative settings.

## Evidence boundaries

Local tests execute CPython against the candidate application code and simulated
hardware. The eight new preservation tests exercise the real signed installer
and a fresh settings loader, but do not emulate real FAT writes, physical flash,
Wi-Fi authentication, sensor-persistent calibration, or full application boot.
Virtual input evidence remains input conformance only. USB/reference-device
results from #25 remain scoped to that original image. Do not label the combined
candidate as production-qualified until its own hardware evidence is recorded.
